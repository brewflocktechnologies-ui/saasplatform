## Global Constraints

- Overview §4 applies. Additionally:
- Purge is never exposed to widget or agent principals; it never runs as one unbounded statement; each batch is its own transaction of at most `batchSize` conversations.
- Eligible = not purged AND ((`status = 'RESOLVED'` AND `resolved_at < cutoff`) OR (`archived_at IS NOT NULL` AND `archived_at < cutoff`)) (Plan 01 ruling R-P25: archived conversations follow the same retention clock as resolved ones).
- Purge deletes `messages`, `message_attachments`, `conversation_read_cursors` and `outbox_events` (`aggregate_type = 'conversation'`; their payloads embed message bodies) of eligible conversations and sets `conversations.purged_at`, `status = 'RESOLVED'` with `resolved_at = COALESCE(resolved_at, now)` (changes only rows eligible by their archive time alone, so purged ⇒ `RESOLVED` ∧ archived, R-P25), `archived_at`/`archived_by` when not yet archived, `archive_reason = NULL`, `last_message_preview = NULL` and `version = version + 1` (a purge is a state write, Plan 01 ruling R-P9; it appends no outbox row, emits no realtime event and writes no state event — `purge_runs` is its audit, R-P25), and removes the free-text `reason` from those conversations' state-event `details` (Plan 01 ruling R-P31 M10); it never deletes `conversations` or `conversation_state_events` rows (audit), and never touches tenants on `legal_hold` — the hold is re-checked before every batch (R-P31 M9).
- Dry run writes a `purge_runs` row with `dry_run = true` and counts, and changes nothing else.
- A `cutoff` override is accepted only when `app.local-dev.enabled=true` (local verification); otherwise the cutoff is `now − resolved_retention_days`.
- Metrics and logs never include message bodies, tokens or secrets.

## Review Focus

1. A conversation resolved long ago but **reopened** (status `OPEN`) is not eligible even though `resolved_at` is old (`RetentionIT.reopenedConversationIsNotEligible`).
2. A batch fails midway (injected SQL failure) → earlier batches stay committed, the run is `FAILED` with `last_error`, a rerun completes the rest without double counting (`RetentionIT.failedBatchIsRecordedAndRerunCompletes`).
3. `maxBatches` is reached with eligible rows remaining → run `COMPLETED` with `batches = maxBatches` and remaining rows untouched, so an operator can rerun (`RetentionIT.purgeStopsAtMaxBatches`).
4. The admin token is sent to a widget route or a widget token to an admin route → 401/403, never a purge (`AdminApiIT.principalTypesDoNotCross`).
5. `/actuator/prometheus` is reachable without auth outside the `local` profile → it must not be (`ObservabilityIT.prometheusOnlyInLocalProfile`).
