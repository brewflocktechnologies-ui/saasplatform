# Conversation Platform — Plan 07: Local Platform, Race Tests, Load Tests, Final Verification (Phases 11–12, 17–19)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Read `2026-10-27-conversation-platform-00-overview.md` first (D19, D20, §4). Depends on Plans 01–06.

**Goal:** One documented Compose command that starts the whole platform for a new developer; cross-cutting race tests with SQL invariants; a reproducible load harness that speaks the real Centrifugo protocol with the seven profiles of master spec 14.6; measured reports; a final verification pass (clean start, full suites, licence/secret/reference-tree checks); and the final report, test report and handover.

**Architecture:** No new product code except `PlatformRaceIT`/`Invariants` (test scope) and the Node load harness under `tests/load/` (official `centrifuge` SDK over Node 24's global `WebSocket`, API via `fetch`). Reports are Markdown + JSON under `docs/testing/`.

**Tech Stack:** Docker Compose v5, Node 24, `centrifuge` 5.8.0, Node 24's global `WebSocket` for the `centrifuge` SDK (no new dependency), PowerShell `verify-local.ps1`, Maven.

**Spec:** master spec 1 (scale objective), 13, 14.4, 14.6, 17, 18, 19.

## Global Constraints

- Overview §4 applies. Additionally:
- Load numbers are reported only from runs that completed, with hardware, durations, client counts and failure counts; the 10,000-client target is marked "not validated" unless a run at that size met the thresholds.
- Clean-start verification uses a separate Compose project name (`-p chat-platform-verify` on every command) so no existing volume is touched. It runs on the default host ports after stopping the main stack (volumes kept): shifted ports do not work without product changes, because the widget image bakes `localhost:8080`/`:8000` at build time and Centrifugo's `allowed_origins` and the backend CORS list name ports 3000/5173.
- The harness must not model WebSocket clients as HTTP users: every simulated visitor and agent holds a real Centrifuge connection and subscription.
- Never run `docker compose down -v`.

## Review Focus

1. A developer with a fresh clone (no `.env`) runs the documented command and reaches the two URLs with everything healthy in one go (`T5 clean-start check`).
2. Contact send and agent resolve race → the final state is either `OPEN` with the message and a `REOPENED_BY_CONTACT` event, or `RESOLVED` with the message's `sequence` ≤ the `RESOLVED` state event's `details.lastSequence` (both written under the conversation row lock; compared by `sequence`, not by timestamps, which come from two clocks — Plan 01 ruling R-P31 M7); never a lost message or a message with no outbox row (`PlatformRaceIT.sendRacesResolve`).
3. Two agents issue conflicting commands with the same `expectedVersion` → exactly one 200, one 409 `STALE_VERSION`, one state event (`PlatformRaceIT.conflictingAgentCommandsWithVersion`).
4. The reconnect-storm profile reconnects 50% of clients within 2 s → every client converges (all sequences present) and the duplicate ratio is reported (`tests/load` reconnect-storm report).
5. Tenancy skew: 90% of traffic in one tenant → the quiet tenant's p95 send latency stays within the documented threshold (`tenancy-skew` report).
